## 站长前言
> [!WARNING] 给站长的提醒
> 如果你是站长，希望你看完这些思路后能顺手把相关隐患补掉。

## DNS 相关
### DNS 历史解析记录
如果目标网站曾直接解析过源站，可以通过一些查询 DNS 历史解析记录的工具找到源站地址。

> [!TIP] 预防方法
> 更换 IP 后不要再把域名直接解析到服务器上，最好接入一层 CDN。

### 子站扫描
有些 CDN 限制接入数量，可能子站就没接入 CDN，可以通过扫描二级域名来寻找子站的源站地址，大概率也是主站的源站地址。

> [!TIP] 预防方法
> 把子站也接入 CDN，哪怕只是 Cloudflare 这种基础方案。

## CDN 相关
### CDN 解析源站
有些 CDN 在流量包用完后会把域名直接解析回源站，所以把流量刷完，就能逼它暴露源站。

> [!TIP] 预防方法
> 使用不限量的 CDN，例如 Cloudflare；或者把 CDN 配成达量后直接停止解析。

## 源站相关
### 软件漏洞
例如博客程序的评论回复邮件，在邮件里很容易泄露源站 IP。

> [!TIP] 预防方法
> 停用此类插件，发送邮件时单独准备一台邮件服务器，或者直接使用成熟的第三方发信服务。

### 全网扫描
如果目标网站套了 CDN，你可以用一些全网扫描的工具，把全网 IPv4 地址扫一遍。如果某台不属于 CDN 的服务器返回了这个域名的有效 SSL 证书，那么它很可能就是此域名的源站服务器。你可以使用 [censys][1] 来实现全网扫描。

> [!CAUTION] 预防方法
> - 给默认站点配一张与域名无关的证书（或者直接拒绝握手），避免别人用 IP 访问时看到该服务器所对应的域名。
> - 设置防火墙，拒绝所有默认入站请求，只对白名单 IP 放行，例如 CDN 节点、搜索引擎和你自己的常用出口 IP。

### 关于 CDN 引发的一个小问题
#### 在使用 CDN 后，源站日志均记录为 CDN 节点 IP 的解决方案
如果您也使用 Nginx，那么请在 Nginx 的配置里加入下列参数配置
```bash
nano /etc/nginx/nginx.conf
```
```nginx
    # 把下面的网段换成你所用 CDN 的回源网段。不要填 0.0.0.0/0，否则任何人都能伪造来源 IP。
    set_real_ip_from   192.0.2.0/24;
    real_ip_header     X-Forwarded-For;
    real_ip_recursive  on;
```
